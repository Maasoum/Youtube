# مسیرهای روشن / BrightPaths

وب‌سایت فروش دوره‌های آنلاین هوش مصنوعی برای کودکان ۸ تا ۱۴ سال. این سایت
ویترین و مرجع فروش است؛ محتوای دوره در سامانه‌ی سرویس‌دهنده میزبانی می‌شود.

## اجرا

```bash
npm install
npm run dev
```

اسکریپت‌های دیگر:

```bash
npm run typecheck   # بررسی تایپ‌ها
npm run build       # build تولیدی
npm run preview     # پیش‌نمایش build
```

## اتصال به بک‌اند

به‌صورت پیش‌فرض لایه‌ی داده روی API واقعی (`/api/v1`) با کوکی نشست کار می‌کند.
درخواست‌ها با `credentials: "include"` می‌روند، توکن CSRF از `/auth/csrf`
گرفته و در هدر `x-csrf-token` فرستاده می‌شود و هیچ توکن یا کلید لایسنس در
`localStorage` نوشته نمی‌شود. کلید کامل فقط پس از «نمایش» و به‌صورت موقت
(۶۰ ثانیه با پاک‌شدن خودکار) در state کامپوننت می‌ماند.

```bash
# اجرا با بک‌اند واقعی (Fastify روی ۳۰۰۰)
npm run dev

# اجرا بدون بک‌اند، با mock adapter
VITE_USE_MOCK=true npm run dev
```

- در توسعه، Vite مسیر `/api` را به `VITE_API_PROXY_TARGET` (پیش‌فرض
  `http://127.0.0.1:3000`) پروکسی می‌کند؛ در production این کار با
  `deploy/nginx/brightpaths.conf` انجام می‌شود.
- `APP_URL` بک‌اند باید دقیقاً همان مبدأی فرانت باشد (پورت هم مهم است)، چون
  نگهبان CSRF هدر `Origin` را با آن مقایسه می‌کند.
- فهرست کامل ناهماهنگی‌های فرانت/بک‌اند و نحوه‌ی رفع آن‌ها:
  `docs/frontend-backend-mismatches.md`.
- پیکربندی nginx شامل CSP سخت‌گیرانه، HSTS، `X-Frame-Options`، پروکسی
  `/api` و `/uploads`، fallback مسیرهای SPA و کش طولانی دارایی‌های hash‌دار
  است.
- برای روشن‌ماندن دائمی حالت mock، `VITE_USE_MOCK=true` را در
  `.env.development.local` بگذارید؛ این فایل فقط در `npm run dev` خوانده
  می‌شود و `npm run build` همیشه نسخه‌ی واقعی را می‌سازد (پرچم mock در
  production نادیده گرفته می‌شود). `mockAdapter` با import پویا بارگذاری
  می‌شود و در بسته‌ی اصلی production نیست.

## ورودهای نمایشی

این حساب‌ها فقط وقتی `VITE_USE_MOCK=true` باشد وجود دارند (mock adapter
درون‌حافظه). برای بررسی داشبورد و پنل مدیریت:

| نقش | ایمیل | رمز عبور |
| --- | --- | --- |
| والد | `parent@example.com` | `demo1234` |
| مدیر | `admin@brightpaths.example` | `admin1234` |

در صفحه‌ی ورود نیز یک بخش «دسترسی نمایشی» برای ورود سریع وجود دارد.

## فونت برند

فونت «پیدا» به‌صورت self-host در `public/fonts/` قرار دارد و در `src/index.css`
با `@font-face` برای دو وزن ۴۰۰ و ۷۰۰ (به‌همراه فالبک `woff` و `local()`)
معرفی شده است. `index.html` هر دو فایل `woff2` را preload می‌کند.

```bash
curl -I http://localhost:5173/fonts/PeydaWeb-Regular.woff2
# باید 200 و Content-Type: font/woff2 برگردد
```

اگر مرورگر همچنان Tahoma نشان می‌دهد: `dist/fonts/` را در استقرار بررسی کنید،
build را دوباره بگیرید و کش مرورگر را با hard refresh پاک کنید.

## ساختار

- `src/api/` — لایه‌ی داده‌ی تایپ‌شده (`api.submitLead`, `api.listCourses`,
  `api.listPosts`, `api.listFaqs`, `api.listTeachers` و APIهای حساب/سفارش)؛
  `http.ts` کلاینت fetch با CSRF، `realAdapter.ts` نگاشت پاسخ‌های Fastify و
  `mockAdapter.ts` داده‌ی توسعه
- `src/data/mock.ts` — داده‌ی نمونه‌ی مقاله‌ها، مربیان و پرسش‌های صفحه‌ی اصلی
- `src/config/brand.ts` — تنها منبع نام برند
- `src/config/images.ts` — متن جایگزین مرکزی تصویرسازی‌ها
- `src/config/purchase.ts` — مهلت تحویل لایسنس، بازه‌ی بازگشت وجه و قواعد سفارش
- `src/components/` — کامپوننت‌های مشترک، لایه‌ی سایت، دوره، داشبورد و ادمین
- `src/pages/` — صفحه‌های مسیرها
- `src/lib/` — قالب‌بندی فارسی، اعتبارسنجی Zod و resolver
- `src/lib/discount.ts` — موتور تخفیف به‌صورت توابع خالص و قابل استفاده در سرور

## جریان خرید نمایشی

- دوره‌ها: `/courses` با فیلتر سن و سطح، صفحه‌ی دوره و سبد تک‌دوره‌ای در
  `/checkout/:slug`.
- کدهای تخفیف نمونه: `BRIGHT20` (۲۰٪ تا سقف ۳۰۰٬۰۰۰ تومان، حداقل سفارش
  ۵۰۰٬۰۰۰ تومان) و `FIXED200` (۲۰۰٬۰۰۰ تومان، حداقل سفارش ۱٬۰۰۰٬۰۰۰ تومان).
- پس از پرداخت، صفحه‌ی `/payment/callback?state=success|failed|pending|error`
  نتیجه را نشان می‌دهد؛ بدون پارامتر `order` این صفحه یک پیش‌نمایش است.
- تحویل لایسنس، بازه‌ی بازگشت وجه و متن قانونی از `src/config/purchase.ts`
  خوانده می‌شوند. صفحه‌های حقوقی فعلاً پیش‌نویس‌اند و نشان «نیاز به بازبینی
  حقوقی» دارند.

## نکات پیاده‌سازی

- همه‌ی متن‌ها فارسی و RTL هستند؛ ارقام، قیمت و تاریخ‌ها با `Intl` فارسی
  نمایش داده می‌شوند.
- هیچ درخواست شبکه‌ای به بیرون، CDN، تصویر خارجی یا ویدیو ندارد. تصویرها
  SVG داخلی هستند.
- لایسنس‌ها و پرداخت‌ها شبیه‌سازی‌شده‌اند. کدهای لایسنس نمونه ساختگی‌اند و
  ایمیل واقعی ارسال نمی‌شود.
- برای فعال‌کردن فونت Peyda، دو فایل woff2 را طبق
  `public/fonts/README.md` اضافه کنید؛ تا آن زمان فالبک Tahoma استفاده می‌شود.
- صفحه‌ی اصلی شامل هیرو، ویژگی‌های تعاملی، دوره‌های محبوب، مواد آموزشی،
  کاروسل مربیان، وبلاگ، پرسش‌های متداول و فرم عضویت در خبرنامه است.
- برای بازنشانی داده‌ی نمونه، کلیدهای `brightpaths.mockdb.v4`،
  `brightpaths.session.v1`، `brightpaths.leads.v1` و `brightpaths.contact.v1`
  را از localStorage حذف کنید.

## پنل کاربر و پنل مدیریت

- پنل کاربر: `/dashboard` با صفحه‌های دوره‌های من، سفارش‌ها، رسید قابل چاپ،
  اعلان‌ها و پروفایل. کد لایسنس فقط پس از `api.revealLicense(id)` نمایش داده
  می‌شود؛ تا پیش از آن به‌صورت `••••` است و در پاسخ فهرست سفارش‌ها قرار ندارد.
- پنل مدیریت: `/admin` با داشبورد آماری و نمودار SVG دست‌نویس، صف تحویل لایسنس
  (`/admin/fulfillment`)، سفارش‌ها، لایسنس‌ها (`/admin/licenses`)، کاربران
  (`/admin/users`)، دوره‌ها، تخفیف‌ها (ساخت انبوه و گزارش مصرف)، وبلاگ با
  ویرایشگر Markdown و پیش‌نمایش، پرسش‌های متداول، مربیان، پیام‌های تماس،
  لیدها، لاگ عملیات و تنظیمات.
- در `/admin/licenses` جست‌وجو با ایمیل یا شناسه‌ی سفارش انجام می‌شود. کلید
  کامل فقط با دکمه‌ی «نمایش کلید» از `revealLicense` دریافت می‌شود و همان
  نمایش یک رکورد `license.revealed` در گزارش ممیزی می‌سازد.
- مهلت SLA صف تحویل از تنظیمات عمومی (`/admin/settings`) خوانده می‌شود؛ مقدار
  اولیه‌ی آن `purchaseConfig.fulfillmentSlaHours` است و تغییر آن روی هشدار
  دیرکرد و متن صفحه‌ی خرید اثر می‌گذارد.
- درصد مالیات تنظیمات (پیش‌فرض صفر) روی مبلغ نهایی سفارش اعمال می‌شود و در
  تسویه‌حساب، رسید و جزئیات سفارش نمایش داده می‌شود. متن Markdown مقاله هم
  ذخیره می‌شود و صفحه‌ی `/blog/:slug` آن را با پشتیبان‌گیری از بخش‌های قدیمی
  نمایش می‌دهد.
- تنظیمات درگاه پرداخت در `/admin/settings/payment` است. پس از ذخیره‌ی توکن
  PayPing فقط ماسک `••••ab12` نگه داشته می‌شود؛ توکن کامل نه در adapter، نه
  در localStorage و نه پس از ذخیره در فرم باقی نمی‌ماند. فعال‌سازی درگاه فقط
  با توکن ذخیره‌شده ممکن است و «تست اتصال» یک بررسی نمایشی است.
- خروجی CSV سفارش‌ها، تخفیف‌ها، گزارش مصرف و لیدها در مرورگر ساخته می‌شود و
  به سرور ارسال نمی‌شود. همه‌ی عملیات حساس مدیریتی یک رکورد در لاگ عملیات
  ثبت می‌کنند.
